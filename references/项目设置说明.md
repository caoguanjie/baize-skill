# 项目设置说明

`references/项目设置.md` 记录“这个项目长什么样、右栏用哪些层名”。它在 Skill 目录里，随使用者的项目一起提交；`docs/链路全景/` 只放链路文档。

首次使用找不到项目设置时，按本文勘察、起草，交给用户确认后再写入。之后每次调用先读它。修改任何一行都要先向用户提议、得到同意。

## 首次勘察（只读）

只读文件和目录，不运行项目、不安装依赖、不改任何文件。

1. **项目形态**：看依赖清单和目录（`package.json`、`pom.xml`、`go.mod`、`requirements.txt`、`composer.json`、`Gemfile`、`*.csproj`、`android/`、`ios/` 等），判断是纯前端、纯后端、前后端都有、带原生端，还是定时任务或脚本类项目。大仓库里的子项目只看当前目录。
2. **入口种类**：找用户或系统从哪里进入业务。常见位置：页面路由表、菜单配置、接口路由注册、定时任务配置、消息消费者注册、命令行入口。记下每类入口在哪个文件，后面找入口时直接搜这些位置。
3. **资料**：有没有接口契约（OpenAPI、Swagger 等 JSON 文件）、需求文档目录、旧的流程文档或 Wiki。旧资料默认当线索，以代码为准。
4. **代码图谱工具**：检查当前会话实际可调用的工具。推荐但不强制 `codebase-memory-mcp`；已接入时按[源码图谱 MCP](源码图谱MCP.md)核对索引归属与范围，没有就用文本搜索。首次只读勘察不下载、不安装、不建索引；用户明确希望接入时另行处理。
5. **右栏层名**：按目录结构提出 3 到 8 个层名，每层写一句“代码在哪、写什么”，交给用户确认。层名用中文，以「层」或「服务」结尾更易读。

| 项目形态 | 层名示例 |
| --- | --- |
| 纯前端 | 页面层、组件层、状态层、请求层 |
| 纯后端 | 路由层、服务层、数据层、外部服务 |
| 前后端都有 | 页面层、状态层、接口层、服务层、数据层、外部服务 |
| 带原生端 | 再加原生层 |
| 定时任务、脚本 | 调度层、处理层、数据层 |
| 有消息队列 | 再加异步层 |

「能力」层固定可用，指向 `docs/链路全景/能力/`，不用写进设置。

## 起草与确认

把下面的模板填好，连同勘察依据（在哪些文件看到什么）一起交给用户。**停下等确认**，用户改完或同意且允许写入后，写入 `references/项目设置.md`，再继续用户原本的请求。明确只读时，草案只留在回复；确认后作为本轮临时设置使用，不落盘，说明缺少设置文件时 `check` 不能运行。

## 模板

```markdown
# 项目设置

> 首次使用时由白泽勘察起草，用户确认后写入。修改前先征得同意。
> 最后确认：YYYY-MM-DD

| 设置 | 值 | 谁用 |
| --- | --- | --- |
| 项目形态 | 前后端都有 | AI |
| 入口位置 | 页面路由 `web/src/router/index.ts`；接口路由 `server/routes/` | AI |
| 需求资料 | 无；从代码入口开始 | AI |
| 旧资料 | `docs/old/`，当线索，以代码为准 | AI |
| 代码图谱工具 | 无，用文本搜索 | AI |
| 接口契约 | `api/openapi.json` | 脚本 |
| 右栏层名 | 页面层、状态层、接口层、服务层、数据层、外部服务 | 脚本 |
| 卡片扩展字段 | 无 | 脚本 |

## 层名说明

| 层名 | 代码位置 | 写什么 |
| --- | --- | --- |
| 页面层 | `web/src/pages/` | 页面、按钮、跳转 |
| 服务层 | `server/services/` | 业务编排、事务 |
```

## 接入源码图谱后更新设置

接入规则已经写在 `SKILL.md` 和[源码图谱 MCP](源码图谱MCP.md)里。使用者安装后需要的是更新本项目设置，不是重写 Skill 的通用规则，也不是修改 `chain.mjs`。

安装完成、当前会话能实际调用、索引范围已核对后，提出以下设置变化。用户的安装请求已经明确包含更新白泽项目设置时，按该授权执行；否则先取得同意。只改相关行，保留现有项目形态、层名、契约和经验。

| 设置 | 填写内容 | 谁用 |
| --- | --- | --- |
| 代码图谱工具 | `codebase-memory-mcp`；结构查找优先图谱，字面检索与覆盖不足时直接查源码 | AI |
| 图谱项目 | `list_projects` 返回并经根路径核对的精确项目标识，不猜名称 | AI |
| 图谱范围 | 索引根与当前目录的关系；允许检索的子目录，路径如何转为相对当前目录 | AI |

以上是填写说明，不是已经连接的默认值。记录的是项目偏好与范围，不是永不过期的“可用”保证；后续每次仍以当前会话工具和索引状态为准。

若 `项目设置.md` 尚不存在，先起草完整设置并让用户确认；明确只读时仅在回复给建议，不落盘。安装失败或当前会话尚未连上时，不把「代码图谱工具」写成已启用，继续使用原有搜索方式。这个设置不影响文档目录和源码锚点基准。

## 脚本读哪几行

`chain.mjs check` 只读「设置」列为下面三项的行，其余行给 AI 看：

| 设置 | 写法 | 作用 |
| --- | --- | --- |
| 接口契约 | `无`，或相对当前目录的路径，可加反引号 | 核对锚点表里的 `接口 \`POST /api/x\``。写 `无` 或文件不存在时跳过接口核对，每份含接口的文档给一条提示 |
| 右栏层名 | 用 `、` 分隔的名称 | 卡片标题里的层名不在其中就报「未知层名」。缺这一行时 `check` 停下，提示先完成首次使用 |
| 卡片扩展字段 | `无`，或用 `、` 分隔的名称 | 在通用字段之外允许的卡片字段，例如 `组件`、`Prompt` |

缺少 `项目设置.md` 时，`check` 以退出码 2 停下；`refs` 不依赖设置，照常运行。

设置按脚本所在位置查找：`scripts/` 的上一级 `references/项目设置.md`，会跟随符号链接。多个客户端共用一份 Skill 时，只在真实目录里保留这一份设置。
