# 源码图谱 MCP

`codebase-memory-mcp` 是白泽推荐的可选源码检索工具，[官方仓库为 DeusData/codebase-memory-mcp](https://github.com/DeusData/codebase-memory-mcp)。它提供代码索引、定义查找、调用关系追踪和源码片段读取。白泽负责确认业务入口与范围、核对事实、组织链路文档；MCP 帮忙缩小要读的源码范围。

```text
白泽：业务问题 -> 确认入口与范围 -> 按业务整理地图
                         |
                         v
MCP：搜定义 -> 追调用/装配线索 -> 读相关源码
                         |
                         v
白泽：核对真实分支 -> 写图和锚点 -> check
```

没有这个 MCP，白泽仍可用文本搜索和文件读取完成工作。不要承诺固定速度或 Token 节省比例，也不要把 MCP 当作事实裁决器。

## 1. 接入状态

先读 Skill 内的 `references/项目设置.md`，再看当前会话是否实际开放相应工具。下文工具名是短名，各客户端的完整前缀、参数和可用能力以实际工具列表为准，不硬编码某个客户端的前缀。

| 情况 | 怎么做 |
| --- | --- |
| 设置明确不用，或已有另一种图谱工具 | 尊重选择，照原方式工作，不反复推荐安装 |
| 工具可调用，索引属于当前项目 | 按需使用，仍核对范围与新鲜度 |
| 配置写着已安装，但当前会话看不到工具 | 如实说明可能需要重新加载连接或重开会话；不能假装已接通 |
| 工具没安装 | 用文本搜索继续；用户主动想安装时才进入安装流程 |
| 无匹配索引 | 说明需要本地索引；已获当前范围的索引授权才建立，否则先用文本搜索 |
| 服务失败、索引过期、覆盖不全 | 报告本次缺口，直接读源码补证；不以重装或反复重建索引掩盖失败 |

首次检查用 `list_projects` 找候选索引；用 `index_status` 核对其根路径和状态，不能只因项目名字相似就选择它。有分页时继续到能够确定当前项目为止。只有用户已授权、当前项目尚无索引，或确认大型外部变更后确实需要立即刷新时，才考虑 `index_repository`。

索引会写入本地数据，不属于纯只读勘察。工具能用也不自动授予安装、扫描目录外项目、写索引或修改 MCP 配置的权限。

## 2. 按问题选工具，不每次查全项目

| 这一步要弄清什么 | 优先工具 | 范围控制 |
| --- | --- | --- |
| 名称不清楚，找业务对应实现 | `search_graph` | 用业务词、近义词，命中后加文件或类型范围 |
| 已知函数、类或路由 | `search_graph` | 先取得准确 qualified_name，再读源码 |
| 谁调用它、它交给谁 | `trace_path` | 从入口开始，按需设方向与深度；不要把全项目调用图塞进上下文 |
| 一个函数实际怎么处理 | `get_code_snippet` | 读取搜索已确认的符号，不凭空拼 qualified_name |
| 界面文案、配置键、字符串分发 | `search_code` 或文本搜索 | 按目录或文件类型缩小范围 |
| 需要看某个模块的组织 | `get_architecture` | 只看相关目录和所需方面，不默认请求全部架构 |
| 确有多跳或聚合关系问题 | `query_graph` | 限制返回行数，不为简单查找写全图查询 |

已经从链路锚点获得准确文件和行号、只需核对一小段源码时，直接读取，不为了走工具流程重新搜索。还需要探索定义或上下游时再用上表；`refs` 已有命中也不必先拉全项目架构。

读结果中的 `has_more`、`next`、`source_truncated` 等实际分页或截断提示。需要完整结论时补齐相关页或源码；已经有足够证据就停止，不为了“用了图谱”重复拉全量结果。

图谱给出的边是追查线索。遇到注入、事件、反射、状态机或跨服务调用，仍需按[已知断点](已知断点.md)核对真实装配、注册和配置，不能把推断关系直接画成事实。

## 3. 覆盖与路径

- 对准备引用的源码文件，用 `check_index_coverage` 核对覆盖状态；声称某范围“没有实现/调用”前，还要检查该范围的覆盖，而不只看搜索结果。
- `skipped` 文件和 `parse_partial` 范围必须直接读源码或文本搜索；没有记录缺口也不保证索引完整。
- 图谱不可用或已确认当前版本没有覆盖查询能力时，改用直接源码核对，并说明未取得索引覆盖证据，不假造工具结果。
- 图谱索引根目录可能是大仓库，而白泽当前目录是其中的子项目。先确认两者关系，只搜索已确认的子目录范围；输出锚点时把路径转成**相对当前目录**，不照抄索引根路径。
- 命中范围外的源码时，默认当外部交接，不擅自扩大业务范围或索引整个机器。输出仍写当前目录的 `docs/链路全景/`。

## 4. 用户让 AI 安装时

安装话术见 [README 的推荐搭配章节](../README.md#推荐搭配源码图谱-mcp)。这是一项显式的接入任务，不是每次画图都执行的步骤。

1. 从 README 指向的官方仓库读取最新安装说明，核对操作系统、CPU 架构、AI 客户端及项目级配置支持。不要复制记忆里过期的下载地址或直接套用全局注册命令。
2. 检查是否已安装、已注册；先展示要下载或执行什么、修改哪个配置文件、索引哪个目录，得到授权后再操作。保留已有 MCP 配置，不整份覆盖；没有项目级配置能力时先说明限制，不擅自改全局配置。
3. 安装与连接分开确认：写了配置不代表当前会话能调用。需要用户许可、重新连接或重启时明确说出来，不声称全自动完成。
4. 在已授权范围建立或复用索引，用一个当前项目的已知符号核对搜索和源码结果。不能只看安装命令的退出码。
5. 接入成功后按[项目设置说明](项目设置说明.md#接入源码图谱后更新设置)更新项目设置；若首次没有设置，按首次勘察起草完整设置，不创建只有 MCP 一行的残缺文件。

如果安装失败，保留原设置，说明失败环节；白泽可继续走文本搜索。本 Skill 不打包 MCP 服务端、安装器或自动安装钩子，也不在日常调用时升级第三方工具。
