# 经验维护规范

经验保存可复用的探查方法：遇到什么卡点、关键误路为什么不通、用什么证据找到真实交接。它帮下一次探查选起点，不代替当前代码事实，也不保存聊天或命令流水。

经验放在 Skill 目录的 `references/探查经验/`，只记录本项目的探查收获，随项目代码提交。发布包里没有这个目录；第一次沉淀经验时按文末模板创建。

## 读写边界

- 开始探查读 `探查经验/_index.md`，只读命中条目的详情；没有命中就按[已知断点](已知断点.md)查当前源码。
- 查询默认只读。明确只读或没有经验维护授权时，只在回复里给候选，不修失效锚点、不写经验。
- 获得维护链路文档授权且没被禁止维护经验时，收尾可以增量维护 `探查经验/` 下的分类文件和索引；仍然不改任务外业务代码，不自动提交或推送。
- 不自动改 `SKILL.md`、本规范、已知断点、项目设置、脚本或测试。经验暴露出流程缺口时报告建议，由用户决定。
- 依据必须来自真实任务中的源码核对、注册关系或复现结果。演练、猜测、搬运旧资料都不算验证；没找到有效方法就写进本次「未核对」，不创建虚假的成功条目。
- 经验可以写本项目的路径和符号。凭据、令牌、个人资料、完整日志一律不写。

## 收尾顺序

1. **筛选收获**：留下会改变下次探查选择的方法或适用限制；没有就不写。优先记关键失败尝试及原因，不复述每条命令。
2. **找已有条目**：按场景、交接机制和有效追法查索引，再读相关详情。同一机制只是业务名不同，不新建；已有条目补证据或边界。
3. **核实证据**：写日期、验证范围、代码版本或工作区状态、可回查的入口或符号、观察到什么。只做了静态核对就注明。没有提交版本就如实写工作区状态，不编造行号、哈希或次数。
4. **判定状态**：按下表处理，不因自信、赶时间或重复跑同一命令提升等级。旧状态和当前证据冲突时，先停用该结论，再记反证。
5. **增量写入**：按机制选中文分类文件，例如 `依赖装配.md`；分类内用稳定的英文小写连字符 ID 作二级标题，索引链接到该标题。没有真实条目时不建空分类文件。写入前核对目标当前内容，保留别人的改动；冲突合并不了就停下报告。
6. **同步索引**：新增、补证、升级、降级或失效后，更新索引对应行，保持同一个 ID。条目失效时保留索引入口和历史依据，不静默删除。
7. **检查与回报**：核对详情和索引状态一致、链接可达、ID 唯一、证据与结论范围相符。回复说明本次复用了什么、新增或更新了哪些 ID 与状态，或说明无新增、仅候选的原因。

## 可信程度

| 状态 | 依据 | 下次怎么用 |
| --- | --- | --- |
| 单次观察 | 一个真实案例验证过，证据可回查 | 先按线索验证本次场景，再采用 |
| 已稳定复现 | 至少两个独立案例印证同一机制，适用条件一致，各有证据 | 条件匹配时优先采用，仍检查本次实际注册、调用或运行结果 |
| 待复核 | 出现反证、适用条件变化或证据失效，有效范围不清楚 | 不作为可靠追法，先重查受影响范围 |
| 失效 | 当前证据明确证明这条追法不再适用 | 只读失效原因避免再踩坑，不执行旧结论 |

独立案例是不同链路或不同的代表性场景。同一输入重跑、重复阅读、复制记录、改写措辞都不算独立印证；证据必须验证了相同机制。

出现反证时保留旧证据，追加反证和最新核对信息，把原条目标为「待复核」；已明确不再适用就标「失效」。只修订受影响的条件。重新使用前按当前范围补证：只有一个有效案例回到「单次观察」，满足独立印证才回到「已稳定复现」，并同步索引。

## 条目格式

每条只讲一种可复用机制。证据可以追加短行，正文不随每次执行扩写。

```markdown
## <稳定-id>

- 名称：<用中文说明这个方法>
- 状态：单次观察
- 卡点信号：<下次遇到什么现象时应命中>
- 适用条件：<机制与必要前提>
- 关键误路：<试过什么、什么证据说明这条路不够；没试过写无>
- 有效追法：<从什么入口，经什么关系，核对到什么结果>
- 适用边界：<不能由此推断什么，哪些条件仍需核对>
- 证据：<日期；案例或范围；版本或工作区状态；最小可回查定位；观察结果；静态或运行验证>
- 反证与修订：<无，或反证、受影响条件、修订理由>
- 最近核对：<实际核对日期>
```

## 空索引模板

第一次沉淀经验时，创建 `references/探查经验/_index.md`，内容如下，再在表里加第一行：

```markdown
# 探查经验索引

每次探查新链路先读本索引，按卡点信号只读相关详情的适用条件、追法和证据；不只凭摘要执行，也不通读全部经验。中途遇到新卡点再补读。

「已稳定复现」在条件匹配时优先采用，仍核对本次实际连接；「单次观察」先验证；「待复核」「失效」不作为可靠追法。没有命中不等于没有调用，转向[已知断点](../已知断点.md)和当前源码。

维护规则见[经验维护规范](../经验维护规范.md)。

| 经验 ID | 卡点信号 | 方法摘要 | 状态 | 详情 |
| --- | --- | --- | --- | --- |
```

索引一条经验一行：ID、卡点信号、方法摘要、状态、`分类文件.md#稳定-id` 链接。不复制长证据和整段追法。

## 合成示意（不是入库记录）

只搜接口名得到多个实现，沿实际注册和构造关系确认了目标，这可以成为一条经验，第一次记「单次观察」。在另一条独立链路再次印证相同条件，给原条目补证并升级。后来发现某些请求会在运行时替换注册的实现，就补反证、先标「待复核」，不能再凭启动注册断定本次目标。

这段只说明经验会被后续证据修正，不代表已经完成任何真实项目验证。
